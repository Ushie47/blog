Continuous Integration и Continuous Deployment (CI/CD) автоматизируют 
процесс сборки, тестирования и публикации программного обеспечения при 
каждом изменении в репозитории. В этом проекте GitHub Actions 
используется для автоматической сборки и развёртывания сайта на GitHub 
Pages при каждом push в ветку `main`.

## Как устроен рабочий процесс

Файл рабочего процесса (`.github/workflows/hugo.yml`) описывает задачу, 
которая:

1. Клонирует репозиторий, включая Git-подмодули (тему оформления)
2. Устанавливает нужную версию Hugo
3. Выполняет сборку сайта командой `hugo --minify`
4. Загружает собранный сайт как артефакт для Pages
5. Развёртывает этот артефакт на GitHub Pages

## Почему это важно

Без CI/CD публикация изменений потребовала бы ручной сборки сайта 
локально и загрузки результата вручную. С этим конвейером каждый 
`git push` автоматически приводит к обновлению живого сайта — именно 
так этот проект развёртывался, начиная с первого этапа.

## Что было усвоено

Работа с этим конвейером выявила реальные проблемы: необходимость 
указывать `submodules: recursive` при клонировании репозитория, 
настройку прав доступа рабочего процесса для записи в Pages, а также 
случай сбоя инфраструктуры GitHub, одновременно затронувшего Actions 
и Pages, — хорошее напоминание о том, что автоматизация всё равно 
зависит от доступности внешней инфраструктуры.
